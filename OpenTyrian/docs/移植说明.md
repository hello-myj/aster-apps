# OpenTyrian 模拟器移植记录

目标是先在 Aster 模拟器运行原版单机引擎，再决定实机优化。没有重写敌人、飞行物理、商店和武器系统；`vendor/upstream/src` 保持原样，平台替换和原定时器派生代码放在 `port`。

## 平台接入

`entry.c` 管理生命周期、协程和虚拟游戏时钟。Binaryen Asyncify 在构建后保存/恢复 WASM 局部变量，独立 256 KiB C 栈保留原引擎跨回调的栈数据。SDK 回调在自己的栈上工作，避免暂停后的 File、菜单数组等局部数据被覆盖。编译时内部导入全部转换为模块内部函数。

`video.c` 保留三块 320×200 索引色画布、原调色板和调色板动画。画面快照转换为 RGB565，最近邻显示到 480×300，再绘制透明触摸按键。只在原版提交新 VGA 画面后 present。

`sdl.c` 将 evdev 键盘和最多十个触点合并为 SDL 键盘事件、按下状态、文本输入，转交原版 `keyboard.c`。多指共享按键使用合并状态，抬起其中一指不会清除另一指仍按住的键。初始化发送 SDL 焦点事件，避免原引擎误判失焦而无限自动暂停。Host pause/resume 清除输入，防止粘键。

`wasi_adapter.c` 通过 Aster 公共 filesystem API 实现原 stdio 所需的 WASI 操作，文件限定在 APP data 下。初始化创建但不截断 `opentyrian.cfg`，使用原版 portable 模式保存配置和存档。

`audio.c` 播放离线生成的原音乐，以四句柄 LRU 播放内存 WAV。启动预读普通/圣诞模式对应的 38 个音效，战斗中换音效不读 SD。`nortsong.c` 原版计时保留，原采样数组使用可释放的小 token，原引擎的音效编号和释放路径仍有效。

## 构建约束

执行 `tools/build.py`，不要把 SDK 编译的中间 AST 当作成品。

中间 WASM 有四个 Asyncify 控制导入与两个内部栈导入。构建脚本仅将明确声明的 LLVM 栈全局访问和 Asyncify 控制转换为内部指令，最后重新执行 SDK verify；不修改 ABI 版本、能力校验或导入允许列表。

`asyncify-ignore-indirect` 依据本次固定源代码审查启用：APP 保留的游戏函数指针仅用于图形设置枚举，stdio 回调只做同步文件操作，不调用 yield；原 OPL 回调和桌面 scaler 不进入 WASM。更新上游或新增间接调用时必须重新审查；若间接调用链能够等待，应删除此优化标志并复测。

真实设备后续需要单独生成 Xtensa AOT、测算固件外可用 RAM、音频内存、栈高水位与 SD 带宽，再测关卡帧率。模拟器 FPS 和堆峰值不能替代设备实测。

## 已知差异

原引擎单机逻辑保留，但音效八路降为四句柄，BGM 使用 MP3 文件循环，独立音乐音量、渐弱和精确循环段尚未接入。桌面全屏/显示器设置不影响 Aster，鼠标飞行与联网未适配。

试玩应覆盖：原版菜单 → Full Game → Episode 1 → 难度 → 商店 → Play Next Level → Tyrian，方向与射击同时按下、暂停/恢复、Esc、保存/加载，以及主菜单 Demo。自动 Demo 不能替代手动开局测试；原引擎只在非 Demo 模式检查窗口失焦。
