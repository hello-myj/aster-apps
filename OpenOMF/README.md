# OpenOMF → Aster 原引擎移植 0.2.14

钢铁交锋，重返旧日擂台。

当前默认工程直接编译 OpenOMF 原引擎，运行原版菜单、驾驶员与机器人选择、单人对战、竞技场机关、AI 和锦标赛流程。战斗、碰撞、动画脚本、投技、连击和驾驶员属性使用上游代码，未继续采用早期预览的简化规则。

已部署微雪 ESP32-S3 3.5B 实机并运行原版自动对战，模拟器也可运行。仍有平台适配差异，帧率尚不足以达到桌面原版体验。当前包需要本地 ABI4.2 音频内存加载候选 SDK/固件。

## 操作

模拟器先点“启用声音”，再点游戏画面取得键盘焦点。

- 菜单：方向键选择，Enter确认，右Shift取消/脚，Esc返回。
- 对战：方向键移动/跳跃/下蹲，Enter拳，右Shift脚，按原方向序列加拳脚出招。
- 方便电脑试玩：WASD方向，Z拳，X脚，C同时拳脚；仅在对战中映射到玩家一当前配置的按键。F8切换到原生键盘模式，以使用原版双人键位。
- 透明按键：左下八方向，右下拳/脚/P+K，右上Esc；支持多个触点。鼠标仅能模拟一个触点，斜方向可直接点斜角按钮。
- 锦标赛姓名可用电脑键盘输入，也可用触摸方向键操作原版字符轮，拳确认。
- 暂停、返回、配置、选手和赛事选择均走原版菜单；Tab或反引号打开原版控制台。

## 构建与运行

SDK位于 ../../aster-sdk，或设置 ASTER_SDK。需要 Python3.11+、Node.js22+；OPENOMF_PYTHON / OPENOMF_NODE 可指定解释器。

```powershell
./tools/build.ps1
./tools/run-sim.ps1
```

默认端口8848。build-engine.ps1保留为build.ps1的兼容入口；app.toml是唯一当前配置。默认构建Xtensa AOT和WASM；build.ps1 -SimulatorOnly可只构建WASM，-Aot保留兼容。生成成功不等于真机加载或运行成功。

构建脚本校验并准备固定版本的WASI libc、LLVM内建库、SDL2/ENet头文件，再准备原版资源。SDK必须包含本次已授权的构建/校验工具修复，见docs/SDK工具修复.md。

资源取自官方OpenOMF0.8.6 Windows发行包（SHA256固定校验），原始游戏数据不提交Git。首次转换PSM音乐需要带libopenmpt和libmp3lame的ffmpeg，可设置FFMPEG。Windows未找到ffmpeg时使用WSL Ubuntu-22.04，可通过OPENOMF_WSL_DISTRO修改发行版。

输出包：dist/xtensa/aster.openomf.ast。外部SD资源：sdcard/aster/apps/aster.openomf/data/resources；配置在data/config，原版CHR存档在data/state/save。安装AST包本身不包含这些外部资源。重复构建保留已有配置和存档。

## 适配结构

- vendor/upstream：OpenOMF源码，固定提交da5f5ad4b9df63300ae6e8e6ad446924dc11b668；与官方电脑版0.8.6源码不是同一提交。
- port：Aster生命周期、键盘/触摸SDL服务、原生文件I/O适配、有界分配器、软件调色板渲染器、原三声道音频后端和配置读写。
- tools：依赖及资源准备、构建、模拟器和官方电脑版对照启动工具。
- src、tools/prepare_assets.py、legacy/0.1.1：早期简化预览的参考材料；当前app.toml不编译它们。不要以旧预览说明判断当前原引擎功能。
- build/dist/artifacts/sdcard：可重建输出，不入Git；项目全部材料保持在OpenOMF文件夹内。

320×200原场景按最近邻放大到480×300，在480×320横屏居中。软件后端实现上游调色板/重映射、阴影、暗色混合和透明度规则，保留原竞技场动态对象。

## 内存、性能与实际验证

当前0.2.14固定4MiB线性内存，内部3MiB有界C堆，Host管理堆384KiB；C堆仍位于APP静态区，避免与Host表面映射重叠。中间VGA帧缓冲由512000B减至256000B，保留索引、重映射、暗色及叠加四通道。

精灵无损压缩常驻，使用128KiB解码LRU；绘制和原像素碰撞读取同一份解码像素。修改表面时转为普通自有副本。原AF/BK文件、动画脚本、招式、AI和碰撞规则不变。音效从SOUNDS.DAT建立索引，按需读取单个完整采样，不再把约480KiB音效整包常驻。

已由用户启动0.2.2的4MiB版本原版DEMO，跨多个竞技场，C堆记录峰值2796544B（约2.67MiB），精灵节省约0.9–1.6MiB。这个峰值不包含Host/固件和AOT，不代表全部机器人、锦标赛与结局的最高值。0.2.3进一步缩减音效常驻后已构建和包校验，但运行峰值仍待实际确认。

设备端需包含本轮AOT加载内存优化的固件：通过WAMR公开所有权接口，加载后回收非XIP的原始AOT镜像；对较大镜像保留未来线性区，减少连续内存被指令副本分割的问题。原ABI4.1结构不变。这些加载优化已在微雪目标编译、刷入并实际运行对战；当前还需ABI4.2内存音效候选固件，见文末最新记录。

模拟器对战约21–23FPS，仅用于逻辑和资源观察，不能推断ESP32S3帧率。当前没有实机运行通过的结论。

实际操作已验证原版菜单、原AI实战、投技/击倒/连击、竞技场机关；锦标赛创建驾驶员、保存原版CHR和重新载入成功。电脑键盘姓名输入及触摸字符轮均已观察；尚未逐台逐招、完整通关或全部锦标赛验收。

## 尚未对齐的平台能力

- 原SOUNDS.DAT通过原调度器的三声道优先级/音高/重复处理播放。四句柄缓存减少重复WAV生成与加载，并清理旧声道的过期句柄引用；超出64KiB的音效会降采样保留完整长度，不截断。
- 原PSM完整曲目离线转换MP3，结束后轮询重播；当前SDK不保证MP3重启无缝。初始声像写入立体声PCM，播放中的实时逐声道声像尚无对应公开接口。
- UDP bind/listen、网络大厅/联机未适配；网络入口会明确失败，不假装连接成功。
- 外部MOD包、外部PNG替换、桌面手柄/震动和原桌面截图输出尚未移植。原版vanilla AF/BK/PCX/DAT/TRN资源路径已接入。

这些差异保留在文档中，不以“原引擎已运行”代替完整功能验收。

## 2026-10-24 实机记录

按用户要求跳过 Flash 备份，已刷入微雪 USB 控制台配置的 ABI4.1 固件，并将 68 个资源文件及 AOT 包经 CRC 校验部署到 SD。0.2.3 启动时原版语言解析大量短距离 SD 寻址触发 5 秒回调超时；0.2.4 的 sd_reader 加入固定 8KiB 缓存和逻辑游标，语言初始化约 0.5 秒，全部初始化完成。实机持续 RUNNING，已显示原版片头、主菜单与虚拟按键。

原版片头约5.95FPS，菜单约4.57FPS，仍需渲染优化；SDK stats中的 fps=60 是请求值。C堆当前观察峰值744752B，尚未进入对战，因此不代表对战峰值。触摸驱动持续报告无效帧，正在等待实际操作确认。日志位于 artifacts/device/deploy.log；尚不能宣称完整实机玩法验证通过。

## 2026-10-25 实机加载与性能修复

默认版本0.2.11，4MiB线性内存、3MiB APP私有C堆、384KiB Host管理堆、32KiB调用栈，开启Xtensa AOT。3.5MiB/2.5MiB私有堆版本在部分机器人组合及连续对战中仍发生分配失败，不作为稳定实机预算。

- 竞技场背景、HAR1、HAR2及arena初始化分开到不同帧回调，加载期间冻结战斗逻辑，保留固件5秒看门狗。原版AI、动作、碰撞和机关算法不删减。
- 稳定精灵优先接管原始稀疏编码流，原解析对象将指针置空，再由解码LRU/表面释放路径拥有；避免同一压缩流重复复制。绘制与像素碰撞仍使用同样的无损解码像素。
- 私有堆维护按地址排序的空闲块链表，分配只搜索空闲块，并在free时合并相邻块；取代有碎片风险的中间next-fit版本。
- 输出RGB565时按32位写入并仅清理黑边；中间Pixel明确4字节对齐。一般绘制预计算横向取样坐标和大图调色映射，保持原像素采样。
- 音效转换保留原始采样/声像计算，合并成较大块SD写入。已增加PCM及logic/draw/present分段日志，fps应从OMF PERF的实际帧数和时间计算，SDK stats中的60为申请值。

0.2.8实际样本：ARENA1约5.37FPS，ARENA4约3.96FPS；与旧0.2.6约2.72FPS不是固定相同机器人组合的严格对照。帧率仍低，不宣称流畅或桌面原版速度。0.2.11已实际加载双Nova及ARENA4，持续运行结果见设备日志与后续记录。

部署诊断可用tools/deploy_device.py --resume --demo（原版随机DEMO），或--demo-stress（首次直接运行双Nova/ARENA4）。它只上传一次性/data/state/device-demo.once，APP读取后删除，下一次正常启动仍为原版片头和菜单；不增加产品设置开关。部署脚本观察完成时要求APP状态RUNNING，上传按文件CRC校验并支持重用已校验资源。

实机产物：dist/xtensa/aster.openomf.ast；本轮日志artifacts/device/deploy.log，构建日志artifacts/device-0211-build.log。SDK/固件的修改与真实验证范围见SDK源码仓库旁的source/aster-firmware/docs/openomf-device-candidate.md。未提交或推送本轮修改。
0.2.11最终实机记录：双FIGHTR10.AF（Nova）+ARENA4已加载（HAR871/886ms，初始化100ms），180秒观察结束RUNNING/err0，并已切换后续原版对战场景。C堆观察峰值2491376B（约2.38MiB），SDK线性内存观测3960832B，上限4194304B；系统仍能分配6块150KiB外部内存，最大连续块至少524288B。这不是全角色/全流程最高值。双Nova高音效负载样本120帧/42055ms（2.85FPS），后续ARENA1样本120帧/22360ms（5.37FPS），不能将普通场景的帧率当作所有场景保证。

最终包2239356B，SHA256 b4005170ac51bb75389d15597199f4cb1b6fa87cbcf2b03ecc961107da43e5f3，SDK严格包校验通过，31个公开Aster导入。一次性DEMO标记已通过设备目录检查确认删除；实机截图位于SDK的source/aster-firmware/build/openomf-device-0211-fight.png。进一步流畅化需要原生批量索引绘制和减少音效SD往返，见docs/SDK音频补齐方案.md的最新实测补充。


## 2026-10-25 当前实机候选 0.2.14

本节取代前文各历史版本的当前状态描述。默认版本0.2.14，4MiB线性内存、3MiB私有C池、384KiB Host堆、32KiB栈；AOT开启。需要本地ABI4.2及audio-effects-memory能力，不能装到仅ABI4.1的旧固件。该扩展尚未作为官方SDK版本发布。

- 0.2.12：新增公开aster_audio_effect_load_memory，从有界Guest WAV复制到Host自有PCM，保留64KiB PCM、四句柄及格式限制；消除临时音效WAV的SD写入与读回。固件、模拟器、契约、校验器与手册同步，旧4.1接口布局保留。
- 0.2.13：SDK CRT在启用-mbulk-memory时使用WASM memory.copy/fill，其他目标保留原实现。AOT仍执行范围检查，没有增加外部libc导入。双Nova实机样本约5.9–6.0FPS；声音数量及招式随原AI变化，不能视为逐帧同负载对照。
- 0.2.14：缓存原始320×200不透明背景的四通道展开结果，调色板仍在最终转换时应用；命中时复用精确像素。缓存256000B包含在原3MiB C池内，场景切换释放，分配压力时可回收，不扩大线性内存。

0.2.14模拟器原版DEMO360帧结束Exit0/trap=null；实机180秒结束RUNNING/err0，跨ARENA4至ARENA0，C池观察峰值2799760B（约2.67MiB）。不同120帧样本约4.0–6.3FPS，仍不够流畅。Host剩余连续块至少524288B，可同时分配6块150KiB；这些均非全流程最高值。SDK stats的60为申请帧率。
