# SDK 构建和校验工具修复（2026-10-24）

本次经用户明确授权，只修改 SDK 的 tools/build.py 和 tools/verify_ast.py；未修改 APP ABI、Host 导入白名单、固件或模拟器运行时。

## 构建器

- 手册声明的 [build].ldflags 之前被读取但未加入最终链接命令。现在在目标文件之后附加静态库，正确解析 libc/libclang 内建函数。
- 编译、CRT 编译和链接工作目录统一为 APP 工程目录，支持手册定义的工程相对路径。
- 对象文件名原先可能把不同子目录的同名源文件映射为同一文件。现在包含源根编号和完整相对路径，根外源使用路径摘要，避免 OpenOMF 的 formats/af.c 与 resources/af.c 等相互覆盖。

## WASM 校验器

- 导出函数编号按无符号 LEB128 解码。原实现按一个字节跳过函数编号，超过127后错位并出现 IndexError。
- 导入表、内存的 limits 按 LEB128 读取，检查字符串长度、UTF-8、章节边界、未知种类和整数长度。
- 保留原版本、包摘要、目标架构、能力、固定 ABI 和导入符号校验；没有放宽规则来接受不合法模块。

## 实际校验

修复后，旧0.1.1包仍通过（20个Aster导入和2个允许的libc内建导入）；原引擎0.2.0包通过，最终导入全部为公开Aster函数，没有SDL、WASI或未解析libc Host导入。原引擎链接177个源文件。

重建本项目需要带有上述修复的SDK。换用另一个SDK安装时请先检查构建器是否支持ldflags以及多字节函数编号；本项目的构建脚本不会自动改写SDK。当前开发机修复文件位于 ../../aster-sdk/tools/build.py 和 ../../aster-sdk/tools/verify_ast.py。
