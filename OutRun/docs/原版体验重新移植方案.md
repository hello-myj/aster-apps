# 原版体验重新移植方案（ZgzInfinity/OutRun）

## 参照与目标

参照是用户之前选择的 ZgzInfinity/OutRun 重制版（上游本地 commit `6882721c99bc79365f815f68d389bf5078129e68`），不是1986街机 ROM。目标仍是 Aster ABI 4、微雪横屏 480×320、触控、SD 外置资源；衡量标准是起跑/计时驾驶/路面与场景透视/车辆操控响应接近该重制版，而非“模拟器启动且无 trap”。旧 prototype 已复制到 `legacy-prototype/`，当前改动保留可逆。

## 渲染与 SDK 适配约束

- 上游默认视口 `921×691`、`SCREEN_Y_OFFSET=130`、`FOV=120`、`CAMERA_HEIGHT=800`、`CAMERA_DISTANCE=1/tan(FOV/2)`、`ROAD_WIDTH=1600`、`SEGMENTL=150`、`drawDistance` 为上游原值。将 y 的渲染偏移与图像坐标按目标屏高比例缩放，不能在 320px 高屏直接加 130；camera/FOV/world 几何维持原单位。
- SDK `gfx.h` 声明 `ASTER_GFX_FRAME_CONTROL` 协议的 BEGIN/END/SET_CLIP 与 CLIP_SUPPORTED。调用前 QUERY 协商能力；SET_CLIP 需要主动事务和同步 graphics 批次。如果宿主无能力则报告并采用线条几何裁剪，不静默假设裁剪可用。
- Aster API 主要提交三角形和 BMP sprite。每帧 draw command 与独立 asset bitmap handle 数受编译/host 预算。地图贴图大，不应全部解码常驻：按可见 drawDistance 缓存，纹理handle上限与峰值解码字节须用 SDK真实统计验证；若因画质/裁切需要 guest framebuffer，只在 surface可写映射能力、提交耗时、应用内存额度都实测后选用。
- `480×320 RGB565=307,200 B`；SDK graphics transaction 协议每帧上限为 153,600 pixels，理论上完整屏刚好等于上限，且不能把整屏 UI 额外算入第二个 transaction。按一次 canvas/frame 渲染统一提交、估计每条道路8–12命令并对原 drawDistance压测，记录批次数、最大命令数、内存峰值和帧耗时。若超预算，先合批/固定视距裁剪，不降低原道路细节再声称符合。
- 音频 SDK API 已存在 `aster_audio_start_file()`、最多4个 native PCM effect handle 等；须以 `aster_audio_get_info`、sim诊断/设备能力确认可用。OGG是否支持需看 SDK实际 codec 描述，不能默认沿用上游 OGG。

## 本轮阶段门

1. 方案和旧版保护：本文件；`legacy-prototype/` 保存旧 main、资源转换脚本、manifest 和已验证 AST。
2. 原始映射：读取并逐函数记录 `Line::projection/renderSpriteInfo/renderCars`、`Map::renderMap/updateMap`、`Biome::addBiome/loadObjects`、PlayerCar驾驶与动画、Traffic AI、Game时序、HUD、Audio；确认当前 SDK bitmap/clip/audio限制和实际API。
3. 实际重新移植：转换原 relief、全量原始 object metadata、开场背景和首局 traffic；用上游同式投影/车辆/时间/HUD驱动 Aster。先可玩，再逐步扩展各地图分支和内容。
4. 原版参照验证：从原模拟器开场、直线、弯道、坡道/背景、方向转弯各存一张基准图；Aster保存相同视点截图。逐项比对地平线、道路宽度/曲线、山坡遮挡、对象间距/缩放、车身方向帧、HUD位置；记录明显差异及具体原因。
5. 生命周期验收：起跑→驾驶计时→关卡时间奖励/检查点→结束/超时→重试；音频能力、每帧命令/耗时/峰值 guest memory 需有实测。至少延长运行测试多个上游 segment，不能以几十帧无错误算体验移植完成。

## 必须继续公开的差距

若未实现所有15张地图/5层原始分支、完整AI与所有车辆颜色/动画、全部HUD动画、菜单设置存档、完整混音与原音频，交付文档要逐项列明。若模拟器或设备音频/API、触控只能单指或 bitmap裁切预算造成体验差异，报告复现命令与数据，请产品负责人确认替代前不要静默删减。

## 当前实际实现（0.2.0，当前模型执行）

上述模块映射为设计记录。实际落地使用 src/port/render.c、game.c、assets.c 与 src/main.c；道路、车辆和输入未拆成原计划中的多个单独C文件。渲染最终采用 SDK 公开的普通可写RGB565 surface，用软件采样保留原图alpha、非等比缩放与坡道遮挡，未使用frame事务clip路线。资源转换保留15张完整地图与终点；当前只迁移红色Ferrari，其他车色及完整菜单未完成。音频经离线转码并按效果容量截短，不是完整SFML音频等价。

实际格式、验证、内存配置和差距以本目录代码移植文档.md及项目README为准。0.1方案和程序已分别存放docs/legacy-v0.1、legacy-prototype，便于恢复。Luna已停止，本轮实现和验证由当前模型完成。
