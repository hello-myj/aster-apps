# OutRun 0.2.0 代码移植文档

上游：ZgzInfinity/OutRun，本地 commit 6882721c99bc79365f815f68d389bf5078129e68。0.1 版未满足原版体验，已保存在 legacy-prototype/。本轮由当前模型执行。

## 源码映射和保留的计算

src/port/render.c 对应原 Line::projection、renderSpriteInfo、renderCars、Map::renderMap。保留 CAMERA_DISTANCE=1/tan(120°/2)、CAMERA_HEIGHT=800、ROAD_WIDTH=1600、SEGMENTL=150、200段前视、baseLine与percent、difX/sumX曲线累加、左右双路、分层道路线条及坡面最大Y遮挡。SCREEN_Y_OFFSET 的130参考像素按691参考高度缩放；玩家车按921×691参考视口分别缩放。背景使用原纹理周期与初始1000像素偏移，前后层以不同速度滚动。软件采样保留源图透明度，写入RGB565。原 HUD 图片与 DisposableDroid 字体用于界面。

tools/prepare_assets.py 对应 Biome::addBiome/addSegment/computeRoadTracks/easeIn/easeInOut、Logger::checkBiomeRelief/checkLevelBiomeSprites 和 Biome::loadObjects。保留各段进入/保持/离开长度、曲率、高度、镜像、宽度与三种地面字段，按原 GROUP_LINES 的终点排除、步长和频率规则生成对象；同一行同一槽位后定义覆盖前定义。Map1 的物体表先放45个起终点素材，再放该地图素材，与上游全局对象编号一致。保存双侧显示轴点、双侧碰撞轴点、碰撞宽度、SCALE、COLLISION、SHOW_TERRAIN。原 checkReliefHillCurve 实际调用 addBiome(enter,hold,enter,...)，转换器保留了这个与声明参数不同的实际行为，避免擅自改变原赛道长度。

src/port/game.c 对应 PlayerCar::accelerationControl/controlCentrifugalForce、Map::updateMap/updateCars 的核心驾驶与进度。采用60Hz固定步长：低档100、高档200、自动换档、100/6.5加速度、50制动加速度、松油门0.75倍自然减速、转向阈值收敛、离心力与路外减速/恢复。地图位置按原每逻辑步加speed推进，图形请求原版60Hz（实际刷新受绘制耗时限制），不会改变固定步长的驾驶速度。碰撞按原图宽与左右碰撞轴点转换到世界坐标；玩家碰撞宽度随参考视口归一化。碰撞旋转、停车、人物动作及0.012单位回中保留为分阶段恢复。车身按原方向/坡度/制动/碰撞帧区间切换，轮胎按地表选择原效果帧。

地图按原五层二叉路线布局选择下一关，沿原 fork 几何拆分双路，加载下一张地图并增加原关卡时间比例。map00 为原 Biome::setGoalBiome 地形和终点对象，终点自动推进、回中、制动至停下。起跑和终点人群的随机布置用固定代表值保证可重复；过场尚未全部逐帧复刻。

main.c 负责 Aster surface、触控/键盘、暂停/恢复和最大150ms的累积步进。输入层保持单触点能力约束，默认自动油门允许同时完成驾驶动作；电脑键盘可以组合方向、油门或制动。AUTO GAS可关闭。所有按住状态在生命周期暂停时清除。

## 外部资源与格式

运行时统一根目录 /data/resources，映射实际 SD 的 /aster/apps/aster.outrun/data/resources。模拟器 --state 指向工程 sdcard/aster/apps，直接使用同一目录；AST不打包大资源。

mapNN.bin 为小端结构：10个u32头字段 magic/count/metas/objects/time/body/checkpoint/id/terrain/road_terrain；12个RGB565颜色；count条20字节地形记录（4float高程/曲率/道路距离和u32镜像）；metas条52字节对象属性（image u32 +12float）；objects条20字节布置（line/object u32、x/y float、side u32）。索引按行和原槽位顺序排序，加载时校验数量和索引。只保留当前地图，绘制无每帧堆分配；缓存未命中才读图。

img/NNNN.r16 的8字节头为4个u16：解码宽、高、原宽、原高。宽的bit15表示含alpha平面。随后为宽×高个RGB565像素；若有半透明源像素，再附宽×高字节alpha。原宽高用于保留原投影尺寸，预缩图用于控制缓存；最大常规320×320，背景适配到不超过1200×128。完全透明像素键值0，黑色保留为近黑。font.r16 是源字体预生成的固定256×96图集。

catalog.json 记录逐图来源、原尺寸与解码尺寸、15张地图和终点、玩家148帧、轮胎28帧、17种交通车、HUD、背景和音乐；catalog.h 是构建生成的只读编号表。当前1156张图，外部资源约43MiB，实际大小以生成结果为准。必需资源缺失会记录错误；地图缺失时在画布显示安装提示，字库缺失则init失败并输出复制SD资源说明。

## 音频适配

使用原 Magical_Sound_Shower 音乐转22050Hz立体声96kbps MP3，通过 aster_audio_start_file 流式播放。原起跑、引擎、制动、碰撞片段转成16000/22050/44100/48000Hz立体声S16LE WAV，在运行时按 audio_get_info 选择采样率。每个效果保留0.315秒以满足SDK的64KiB效果上限，最多预载4个效果，按动作触发或循环。因此音频触发语义已接入，完整SFML长音效、动态音高和混音仍有差异。模拟器需用户点击启用声音；无音频硬件时保持游戏运行。

## 内存和性能

manifest 初始线性内存3MiB、上限4MiB、heap2.5MiB、stack32KiB。RGB565 surface 307200B包含在应用内存；图像缓存硬上限1100000B；字体约49KiB；地图占用随当前地图变化，最大场景对象约2万条。文件句柄在每次读取后关闭，纹理像素按LRU释放，暂停/退出释放音频与图形资源。

ABI4模拟器的普通运行及固定时钟回放分别记录在 artifacts/v2/。诊断平均宿主执行约16–19ms，仅说明该电脑上的执行耗时，不等于设备帧率。真实板卡的线性内存可分配量、RGB565转换/显示提交、音频缓存和总PSRAM峰值未验证。

## 实际验证与边界

构建脚本 tools/build.ps1 转换资源、编译Xtensa AOT并verify，最终日志为 artifacts/v2-build-verify.log。SDK包装器的reader thread偶有编码异常，产物仍需verify和实际运行共同确认。

tools/validate-maps.js 通过原应用菜单依次加载15张地图，各3帧，45帧，无trap，退出日志assetErrors=0；地图截图和诊断保存于 artifacts/v2/maps/。

tools/validate-sim.js 在真实WASM+真实SD目录中以整数毫秒固定时钟运行约70秒、2101个FRAME事件，包含左右转、制动、松开、碰撞恢复以及原音乐/效果API调用。日志、音频事件、截图和诊断保存在 artifacts/v2/。这是输入和运行验证，不代表全游戏画面/玩法已完全一致。

tools/validate-lifecycle.js 以150ms事件步长加速验证计时归零、TIME OVER和重新开局，诊断、截图和事件记录为 lifecycle-*、timeout.png、retry.png。

tools/validate-boundaries.ps1 使用独立夹具，复制未改动的生产game/render/assets代码，从关卡末端状态测路线1→3→5→9→13→终点，然后实际推进终点cutscene至GOAL。结果318帧、5次边界断言、退出0、assetErrors=0。图为 goal-approach.png 和 goal.png。该结果是边界和终点集成测试，不能称作五关全程实驾通关。

原开场GIF的参考帧可从 vendor/upstream/Resources/Gifs/Salida.gif 提取，用于人工比较起跑横幅、车身比例、道路和对象分布。源图和当前多场景截图分别保存，未以GIF或视频替代游戏绘制。
