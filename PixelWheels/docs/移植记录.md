# 移植设计与代码说明

## 原版边界

原版为 Java/libGDX 与 Box2D，Aster 为 freestanding C → WASM/AOT。保留原始资源与数据，重新实现运行层。不能将当前 C 简化物理描述为原版 Box2D 等价实现。

## 对照关系

- 原 `android/assets/championships/*.xml` → 9 赛道目录。
- 原 `core/assets-src/maps/*.ase` 与 `android/assets/maps/*.tmx/tsx` → 分层 RGB565/alpha 图块、材质和碰撞栅格。
- 原 `android/assets/vehicles/*.xml`、Aseprite 车身和 tires → 15 辆车组合图与速度倍率。
- 原 `map/WaypointStore` → 按原始 Waypoints 顺序的路线与计圈。
- 原 `GamePlay`、`Material`、`Wheel`、`Vehicle` → 参考路面速度、横向抓地、驱动与漂移概念的 C 近似求解器；不是逐行完整移植。
- 原 `RacerCameraUpdater` → 前视跟随镜头；当前没有原速度缩放。

## 当前文件

- `src/main.c`：生命周期、文件加载、输入、车辆、AI、计圈、软件 RGB565 渲染与音频事件。
- `src/catalog.h`：从原数据生成的赛道/车辆目录、正弦表和资源上限。
- `tools/prepare_assets.py`：图像转换依赖 Pillow 与 Python 标准库；音频阶段调用 prepare_audio.py，需要 ffmpeg；读取 Aseprite 可见图层、调色板及压缩 cel，组合原背景/前景、阴影与车轮。碰撞采用原 TiledObstacleCreator 实际读取的 obstacle JSON，而非编辑器 objectgroup 辅助形状；矩形/full 使用图块变换，circle 与原版相同不套用图块翻转。
- `tools/build.ps1`：转换、Xtensa AOT 构建及包校验。
- `tools/run-sim.ps1`：480×320 模拟器与虚拟 SD 挂载。

## 格式和预算

PWT1 文件头包含尺寸、图块数量和所有数据偏移；后续为背景/前景索引、逐格材质、每原始 8px 一个碰撞采样、航点、礼盒点和图块像素。运行时校验长度、偏移、图块索引后绑定数据，地图每帧读最多 64KiB，切图时复用静态缓冲。

普通 RGB565 表面每帧 acquire，按 pitch 绘制并单次 present。只绘可见图块；赛车使用原车身/车轮组合图逆向旋转采样。地图选择静止时不重画。触摸分别跟踪 slot，菜单按 DOWN/UP 同一范围触发，移动超限取消点击。

## 0.1.2 音频补齐

- src/audio.c 独立管理原版五段引擎录音的相邻混合、速度音高、漂移持续时间增益、冰面音高和涉水循环。
- src/main.c 接入倒计时/起跑、车与墙/车碰撞、礼盒拾取、涡轮、计圈和结束提示。计圈/结束暂复用原版 points-increase 素材，尚非原版全部事件的一比一复刻。
- SDK 同时最多四个句柄，因此引擎占两个、漂移与涉水共用一个、短提示共用一个；碰撞、涡轮等重叠时按优先级抢占或排队，与原版不限这四路的混音仍有差异。
- tools/prepare_audio.py 从上游素材生成有界 PCM16，完整引擎录音为 16kHz，漂移/涉水为 8kHz；涉水截取 3.8 秒循环。音乐全曲转换到 128kbps 并降低 9dB，无游戏内音乐开关。
- 0.1.2 已构建为 WASM + Xtensa AOT，模拟器实际启动比赛，日志显示倒计时、起跑、各引擎层、漂移、碰撞、涡轮及计圈调用成功；运行诊断 effect=4、trap=null。这不等同于人耳试听验收。随后已将 0.1.2 和音频资源同步到微雪板，以 AOT 启动并确认菜单运行；声音听感待实机试听。


## 0.1.3–0.1.4 实机帧率优化

src/main.c 现在使用定点递增坐标旋转车辆、跳过完全透明前景图块并收紧非透明边界、直接复制完全不透明像素、以象限二分查找原256方向表、预计算静态赛段方向。0.1.4 进一步将图块逐字节 memcpy 改为展开的16位拷贝，常用透明按钮与顶栏采用精确RGB565颜色查表。分辨率仍为480×320，车辆数量与音频资源保持不变。定点旋转采样存在亚像素舍入差异。

两张颜色查表新增262,144 B静态内存，前景元数据约10KiB；0.1.4菜单运行的设备peak原始统计为4,792,320 B，外部堆最大连续空闲块至少1MiB。初始3MiB / manifest上限4MiB配置未改，设备peak须按其统计口径单列。

增加PW COST分项计时（累计毫秒，正常窗口60帧）：sim/audio/bg/cars/fg/ui/present。present代表公开提交调用的墙钟耗时，包含Host处理/等待/传输等，不能仅凭该字段断言是SPI带宽。第一窗口需排除菜单/倒计时累计；0.1.4起跑时重置计数。

旧0.1.2实机country手动驾驶的五个60帧窗口：10815、9307、9891、8059、8083 ms（约5.55–7.45 FPS）。第一轮0.1.3三个窗口：8091、8254、7782 ms（约7.27–7.71 FPS）。手工驾驶路线不完全相同，不能视为严格受控的提升百分比。0.1.3后两个稳定分项窗口车辆约3ms/帧，背景约28ms/帧，UI约29ms/帧，提交约49–50ms/帧。0.1.4已AOT部署并启动，驾驶采样另记录于artifacts/device/perf-0.1.4.log。

采集工具：tools/measure_device.py --seconds 45 --label perf-版本；当前使用WSL共享串口/dev/ttyACM0。调用时先关闭其他串口读取程序。原0.1.2包和源文件备份在artifacts/perf-baseline，便于回退。未新增或运行自动化测试。

## 0.1.5–0.1.6：对齐拷贝与编译选项比较（2026-10-23）

新增copy_pixels：目标按4字节对齐，源同相位时使用32位成对像素拷贝；源目标半字相位不同时，从相邻的对齐源字重组两个像素，保留RGB565像素内容。剩余边缘按16位处理。首次菜单在当前表面上比较memcpy、旧16位和新32位三条路径，各绘制四帧、涵盖奇偶偏移，选择累计耗时最低者，随后菜单覆盖采样内容。此选择是小样本启动计时，不代表所有地图/运行负载的全局最优；没有新增缓存。

微雪O2启动计时：65 / 91 / 60 ms，选择32位。Os启动计时：83 / 91 / 58 ms，也选择32位。0.1.5 O2自动驾驶两个已保存完整窗口为7149、7176 ms（约8.39、8.36 FPS）。0.1.6 Os自动驾驶六窗口为7125、7040、7582、7237、7364、7160 ms，合计360帧/43508ms，约8.27 FPS，范围7.91–8.52 FPS。Os没有可确认的帧率优势，但AOT由97,572 B缩到84,044 B，正式版保留Os。

Os六窗口累计分项均值：背景25.61ms/帧、车辆7.74ms/帧、前景7.97ms/帧、UI14.11ms/帧、present50.33ms/帧。背景较上轮手动驾驶的36ms下降，但演示和手动驾驶画面/路线不同，不能据此给出严格控制下的整体提速百分比。车辆数量、分辨率与音频资源不变；录到race finished 40866 ms（三圈），该数为游戏逻辑时间。

为减少反复人工点击，采样时临时构建自动进入DEMO的包；已恢复正常源码并生成正式菜单包，自动启动代码仅存在artifacts/perf-baseline的采样产物。部署工具新增--observe秒数，以同一串口完整捕获比赛，默认仍15秒。正式0.1.6包127,452 B，WASM35,813 B，AOT84,044 B；内存统计peak仍4,792,320 B。

原始记录见artifacts/device/deploy.log（Os采样开始于设备uptime约01:23:14）；O2末段见perf-0.1.5-autodrive.log。备份0.1.4/0.1.5包和源码均在artifacts/perf-baseline。此次新增APP启动计时与实机性能采样，没有新增自动化测试套件。

### 剩余瓶颈交接

公开surface_present调用仍约50ms/帧，下一步固件侧应分别统计旋转/像素转换、缓冲复制、等待显示任务、总线发送的次数与累计/最大时间，确认占比后处理。App侧仍有背景约26ms/帧的预算；仅靠当前拷贝改动无法达到30FPS。任何原生批量图块绘制扩展均需由SDK正式公开后再接入，当前不调用内部接口。保持相同六车、地图、音乐和连续音效进行前后采样，区分请求fps=30与实际PW PERF窗口。
